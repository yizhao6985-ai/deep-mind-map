## 1. 产品概述

### 1.1 愿景

在本地用用户自己的 AI，把主题或笔记快速变成可编辑、可切换外观、可导出且可再导入还原的思维导图。

### 1.2 产品原则

1. **本地优先**：脑图与配置落盘本机，不依赖产品方云端；可选同步到用户**自有** GitHub 仓库作备份。
2. **AI 自配**：模型与密钥由用户自行配置，成本与隐私可控。
3. **结构可往返**：权威 JSON 导出后再导入，结构、布局与 MapStyle 可完整还原。
4. **单人深度编辑**：聚焦个人学习整理，不做共同编辑。
5. **开源可审计**：应用与文档在公开 GitHub 仓库维护；用户可自建、审计与贡献。注意区分两层 GitHub 用途——**本开源仓库** vs 应用内「同步脑图到用户自己的仓库」（§3.8）。

### 1.3 目标用户

| 角色 | 诉求 |
|------|------|
| 大学生 / 考研党 | 把一门课、一本教材快速结构化，备份与打印复习 |
| 职场自学者 | 用自己的 API / 本地模型整理知识，控制费用 |
| 知识整理型学习者 | 粘贴笔记转脑图，精修后导出分享 |

### 1.4 核心场景

配置 AI → 输入主题或粘贴笔记生成脑图 → 手动精修 / 对节点再调 AI → 切换脑图 Style → 导出；换机或备份时导入 JSON 还原，或通过 GitHub 推送 / 拉取同步到自有仓库。

### 1.5 非目标（MVP 明确不做）

- 共同编辑 / 实时协作 / 局域网房间
- 产品方托管云账号、产品方云同步、订阅计费（**允许**用户自有 GitHub 仓库手动同步）
- 掌握度标记、复习 / 闪卡模式
- 企业 Workspace、白板便签
- 自定义主题编辑器、社区主题市场、逐节点皮肤包
- Git LFS、多人协作 PR 流程、同步 PNG/PDF、产品方代管仓库
- 移动端原生应用
- 后台静默自动同步（仅手动推送 / 拉取）

## 2. 信息架构与界面

```
首次引导 (Onboarding)
    → AI 设置 (AISettings)
    → 个人图库 (Library)
         → 画布编辑器 (CanvasEditor)
              → 导出 / 导入 (ExportImport)
         → 应用设置 (AppSettings)
              → GitHub 同步设置 (GitHubSyncSettings)
```

### 2.1 界面清单

| 界面 | 职责 |
|------|------|
| 首次引导 | 欢迎、配置 AI、连接测试；可跳过（稍后在设置中配置） |
| 个人图库 (Library) | 文件夹浏览、脑图列表、新建 / 打开 / 重命名 / 删除、导入入口；推送 / 拉取入口 |
| 画布编辑器 | 脑图编辑、AI 操作、Style 切换、缩放平移 |
| AI 设置 | Provider、Base URL、API Key、模型、温度、连接测试 |
| 导出 / 导入 | 格式选择、路径选择、无损 / 尽力而为说明 |
| 应用设置 | 图库存储路径、显示名（可选）、外观（应用壳）、关于 |
| GitHub 同步设置 | PAT、owner/repo、分支、路径前缀、测试连接、最近同步状态 |

无产品方云登录墙、无协作房间。GitHub 使用用户自备 PAT，非产品方 OAuth 登录。

### 2.2 桌面布局（编辑态）

顶栏（文件 / 编辑 / AI / 外观 / 导出 / GitHub）+ 左侧图库导航 + 全幅画布。视觉细则见 [design-system.md](./design-system.md)。

## 3. MVP 功能需求

### 3.1 应用壳与本地存储

| ID | 需求 | 验收 |
|----|------|------|
| A-01 | Electron 桌面应用，支持 macOS / Windows（Linux 可选） | 可安装或开发模式启动 |
| A-02 | 图库与脑图本地持久化；默认目录明确，可在设置中修改 | 重启后图库与打开的脑图状态可恢复 |
| A-03 | 无网可用：打开、编辑、保存、导出、导入均不依赖网络 | 断网冒烟通过 |
| A-04 | 中文优先 UI | 全部主流程文案为简体中文 |

**默认存储建议**：用户文档目录下 `DeepMindMap/`（具体路径实现时按平台约定），内含 `library/`、`settings.json`。

### 3.2 图库与脑图 CRUD

| ID | 需求 | 验收 |
|----|------|------|
| L-01 | 文件夹整理脑图（创建 / 重命名 / 删除文件夹） | 图库树正确反映结构 |
| L-02 | 脑图新建、打开、重命名、删除、复制 | 列表与磁盘文件一致 |
| L-03 | 最近打开列表 | 最近 N 条可一键打开 |

术语：

- **Library**：个人图库，本地脑图集合
- **Map / MindMap**：单份思维导图
- **Node / Edge**：节点与连线

### 3.3 画布编辑（单人）

| ID | 需求 | 验收 |
|----|------|------|
| E-01 | 节点增删改、双击或 Enter 编辑文案 | 内容即时反映在画布 |
| E-02 | 拖拽调整位置；父子关系可通过拖放变更（MVP 至少支持作为子节点挂接） | 结构与显示一致 |
| E-03 | 折叠 / 展开子树 | 折叠后子树隐藏，再次展开恢复 |
| E-04 | 单节点颜色等基础样式 | 颜色写入节点并随 JSON 导出 |
| E-05 | 撤销 / 重做 | 覆盖结构、样式、Style 切换触发布局等可撤销操作 |
| E-06 | 画布缩放、平移、适应画布 | 快捷键与手势可用 |
| E-07 | 常用快捷键：新建子节点、兄弟节点、删除、撤销、重做、保存 | 文档化并在帮助中列出 |

### 3.4 自配 AI（Provider）

用户自行配置 AI，请求发往用户指定端点，产品不代理、不计费。

| ID | 需求 | 验收 |
|----|------|------|
| AI-01 | 支持 OpenAI 兼容接口：Base URL + API Key + 模型名 | 配置可保存并用于生成 |
| AI-02 | 支持本地 Ollama（或兼容其 API 的本地端点） | 无 Key 或可选 Key 时可连通 |
| AI-03 | 基础参数：温度、最大 tokens（可选） | 写入配置并参与请求 |
| AI-04 | 连接测试：发送最小请求并显示成功 / 失败原因 | 401、超时、模型不存在等有可读提示 |
| AI-05 | API Key 仅存本机；使用系统安全存储或加密本地存储（实现选型写入技术说明） | Key 不以明文出现在导出的脑图 JSON 中 |
| AI-06 | 未配置 AI 时，生成入口引导至设置；编辑与导出仍可用 | 无崩溃、文案清晰 |

#### AI 能力（画布内）

| ID | 能力 | 说明 |
|----|------|------|
| AI-10 | 主题生成整图 | 输入一句话主题，生成带层级的脑图骨架 |
| AI-11 | 粘贴长文 / 笔记转脑图 | 从文本提取结构生成节点树 |
| AI-12 | 选中节点「展开」 | 为当前节点生成子节点建议并插入（可预览后确认） |
| AI-13 | 选中节点「解释」 | 在侧栏或浮层展示解释，不强制改图；可选「写入子节点」 |
| AI-14 | 选中节点「简化」 | 缩短节点文案或收敛子树（需确认） |

AI 生成中须有明确加载态；失败展示错误码含义与重试入口。

### 3.5 脑图 Style 切换（MapStyle）

整图级一键切换预设外观，**不改变节点文本与树结构**。

| ID | 需求 | 验收 |
|----|------|------|
| S-01 | MVP 内置 3 套：`classic` / `compact` / `card` | 工具条可切换且即时生效 |
| S-02 | 切换影响节点外形、配色层级、连线风格、默认间距 / 布局参数 | 与 [design-system.md](./design-system.md) 规格一致 |
| S-03 | 若切换触发布局重算，整次切换作为一次可撤销操作 | Undo 回到切换前布局与 style |
| S-04 | 当前 `mapStyle` 写入脑图元数据 | 保存 / 导出 / 再打开保持一致 |
| S-05 | 入口：画布工具条「外观」分段控件或下拉 | 中文标签：经典 / 紧凑 / 卡片 |

**不做**：用户自定义主题编辑器、主题市场、逐节点皮肤包。

| 预设 ID | 中文名 | 概要 |
|---------|--------|------|
| `classic` | 经典 | 左右分支、圆角胶囊节点、曲线连线 |
| `compact` | 紧凑 | 更小节点、更密间距，适合大图总览 |
| `card` | 卡片 | 矩形卡片节点、更明显阴影与层级色 |

### 3.6 导出 / 导入（往返还原）

#### 权威交换格式

扩展名建议：`.dmm.json`（或 `.dmm` 内嵌 JSON）。同版本导出再导入须 **无损** 还原：

- 节点树与边
- 布局位置
- 单节点样式（如颜色）
- 当前 `mapStyle`
- 标题与其它元数据

| ID | 需求 | 验收 |
|----|------|------|
| X-01 | 导出权威 JSON，含 `schemaVersion` | 文件可被校验器通过 |
| X-02 | 导入 JSON：新建脑图或覆盖当前图（覆盖前确认） | 往返后视觉与数据结构一致 |
| X-03 | schema / 版本不兼容时阻断并提示 | 不静默损坏数据 |
| X-04 | 导出 PNG / SVG / Markdown / PDF（只读或分享用途） | 文件可打开 |
| X-05 | Markdown 可作为「尽力而为」结构导入 | 允许布局与 MapStyle 丢失；UI 标明非无损 |
| X-06 | 支持从系统对话框选择文件，及拖入图库 / 窗口导入 | 两种路径均可用 |

#### 往返验收标准

同一 `schemaVersion` 下：导出 → 清空或新环境导入 → 节点 ID 或等价结构、父子关系、文案、位置、节点色、`mapStyle` 与导出前一致（允许浮点坐标误差在约定阈值内，如 0.5px）。

### 3.7 导出文档 Schema（文档级）

```json
{
  "schemaVersion": 1,
  "app": "deep-mind-map",
  "exportedAt": "ISO-8601",
  "map": {
    "id": "uuid",
    "title": "string",
    "mapStyle": "classic | compact | card",
    "nodes": [
      {
        "id": "uuid",
        "parentId": "uuid | null",
        "text": "string",
        "x": 0,
        "y": 0,
        "color": "token-or-hex | null",
        "collapsed": false,
        "order": 0
      }
    ],
    "edges": [
      { "id": "uuid", "source": "uuid", "target": "uuid" }
    ]
  }
}
```

说明：若实现采用隐式树（仅 `parentId`），`edges` 可省略，但导入导出须约定一种权威表示并在实现中固定。`schemaVersion` 递增时须提供迁移或明确不兼容提示。

### 3.8 GitHub 同步（用户自有仓库）

将本地 Library 中的脑图以 `.dmm.json` 同步到用户**自己的** GitHub 仓库，用于备份与换机。本地仍为权威工作副本；不同步 AI Key / Provider 配置。

#### 配置

| 配置项 | 默认 / 说明 |
|--------|-------------|
| Personal Access Token (PAT) | 用户粘贴；本机安全存储；建议 fine-grained，权限含目标仓库 `contents: read/write` |
| `owner/repo` | 必填，用户自有或有写权限的仓库 |
| 分支 | 默认 `main` |
| 路径前缀 | 默认 `mindmaps/`；仓库内目录镜像本地 Library 文件夹结构 |
| 显示用 GitHub 用户名 | 可选，仅用于 UI 展示 |

认证方式锁定为 **PAT**；不做产品方 OAuth App。

#### 需求与验收

| ID | 需求 | 验收 |
|----|------|------|
| GH-01 | 设置页可保存 GitHub 同步配置；PAT 掩码显示 | 重启后配置仍在；PAT 不进脑图文件与日志明文 |
| GH-02 | 「测试连接」：用 PAT 访问目标仓库 | 成功 / 失败有中文原因（见错误映射） |
| GH-03 | 「推送到 GitHub」：将图库中脑图写成路径前缀下的 `.dmm.json` 并提交到指定分支 | 远端出现对应文件；commit message 可读（如 `sync: Deep Mind Map`） |
| GH-04 | 「从 GitHub 拉取」：读取路径前缀下 `.dmm.json` 写入本地图库 | 本地可打开且结构完整 |
| GH-05 | 目录镜像：本地文件夹 ↔ 仓库子路径 | 推送后路径与图库树一致 |
| GH-06 | 未配置或连接失败时，推送 / 拉取入口引导至设置 | 无崩溃 |
| GH-07 | 仅手动触发；无后台静默自动同步 | 无定时任务、无保存即推送（除非用户显式操作） |
| GH-08 | **不同步** `AIProviderConfig`、PAT、本机绝对路径 | 抽检远端文件无密钥字段 |
| GH-09 | 冲突处理：同一相对路径下本地与远端内容或 `updatedAt` 不一致 | 弹窗选项：「保留本地」「使用远端」「跳过」；不做自动三路 merge |
| GH-10 | 同步进行中显示进度（文件数 / 当前文件）；可取消进行中的批次（已写入的提交按实现尽量原子或明确部分成功提示） | UI 与 [design-system.md](./design-system.md) 一致 |

#### 错误映射（中文提示）

| 情况 | 用户可见说明 |
|------|----------------|
| 401 | Token 无效或已过期，请重新配置 PAT |
| 403 | 无权限写入该仓库，请检查 Token 权限与仓库访问 |
| 404 | 仓库或路径不存在，请检查 owner/repo 与分支 |
| 网络失败 / 超时 | 网络不可用，请稍后重试 |
| 分支保护等拒绝推送 | 无法推送到该分支，请更换分支或调整仓库设置 |

#### 同步内容边界

- **同步**：`.dmm.json`（含 `mapStyle`、节点、布局等，与导出权威格式一致）
- **不同步**：PNG / SVG / Markdown / PDF、AI 配置、PAT、应用外观偏好（除非另有本地 settings，仍留本机）

## 4. 核心用户旅程

### 旅程 A：首次生成

1. 安装并打开应用  
2. 首次引导配置 Base URL / Key / 模型，点击「测试连接」成功  
3. 图库中「新建脑图」，输入主题或粘贴笔记，AI 生成骨架  
4. 手动增删节点，对难点节点使用「展开 / 解释 / 简化」  
5. 切换 Style 为「卡片」，导出 `.dmm.json` 与 PNG  

### 旅程 B：备份与还原（本地文件）

1. 在机器 A 导出 `.dmm.json`  
2. 在机器 B 安装应用，导入该文件  
3. 打开后结构、布局、Style 与导出前一致  

### 旅程 C：无 AI 纯编辑

1. 跳过 AI 配置  
2. 手动从中心主题搭建脑图  
3. 导出 Markdown / PDF；稍后配置 AI 再使用生成能力  

### 旅程 D：GitHub 同步备份与换机

1. 在应用设置中填写 PAT、`owner/repo`、分支与路径前缀，测试连接成功  
2. 图库或顶栏点击「推送到 GitHub」，等待完成 Toast  
3. 在机器 B 安装应用，配置同一仓库与路径，点击「从 GitHub 拉取」  
4. 本地图库出现对应脑图，打开后结构、布局、MapStyle 与推送前一致  
5. 若两侧均有修改，冲突对话框中选择保留本地 / 使用远端 / 跳过

## 5. 领域模型

| 实体 | 说明 | 关键字段 |
|------|------|----------|
| `MindMap` | 一份脑图 | `id`, `title`, `mapStyle`, `folderId`, `updatedAt` |
| `Node` | 节点 | `id`, `parentId`, `text`, `x`, `y`, `color`, `collapsed`, `order` |
| `Edge` | 连线（若显式存储） | `id`, `source`, `target` |
| `LibraryFolder` | 图库文件夹 | `id`, `name`, `parentId` |
| `AIProviderConfig` | AI 配置 | `baseUrl`, `apiKeyRef`, `model`, `temperature`, `providerType` |
| `MapStylePreset` | 内置外观预设 | `id` ∈ `classic` \| `compact` \| `card` |
| `ExportDocument` | 交换文档 | `schemaVersion`, `map`, `exportedAt` |
| `GitHubSyncConfig` | GitHub 同步配置 | `tokenRef`, `owner`, `repo`, `branch`, `pathPrefix`, `displayName` |
| `SyncRun` | 一次推送或拉取会话 | `id`, `direction` (`push`\|`pull`), `startedAt`, `finishedAt`, `status`, `conflictCount`, `errorCode` |

不含：产品方云用户、订阅、协作会话、Presence。

## 6. 成功指标与约束

### 6.1 指标（本地产品可用质性验收代替增长指标）

| 指标 | 目标 |
|------|------|
| 激活 | 首次启动完成 AI 配置（或明确跳过）并成功保存 ≥1 张脑图 |
| AI 成功率 | 配置正确时主题生成成功率 ≥ 主观可接受；失败有可读原因 |
| 往返 | 同版本 JSON 导出再导入：结构、布局、MapStyle 一致 |
| Style | 三套预设均可切换且可撤销 |
| GitHub 同步 | 配置正确时推送后拉取，结构与 MapStyle 一致；冲突可选手动解决 |

### 6.2 约束

- UI 简体中文优先  
- API Key 与 GitHub PAT 不进脑图文件、不进日志明文  
- 无网：编辑 / 导出 / 导入可用；AI、GitHub 推送/拉取在离线时禁用并提示  
- AI / GitHub 错误：超时、401、403、404、模型不存在等映射为中文说明  

### 6.3 隐私

- 默认所有脑图仅存本机  
- AI 请求内容发送至用户配置的第三方 / 本地端点；设置页需简短披露  
- GitHub 同步将脑图内容写入用户指定的自有仓库；设置页需提示仓库可见性（公开仓库勿放敏感内容）  
- 卸载或清除数据路径前应提示备份导出或推送

| ExportDocument | 可导入导出的交换文档 |
| PAT | GitHub Personal Access Token，本机保存，用于访问用户自有仓库 |
| GitHub Sync | 将本地 `.dmm.json` 手动推送 / 拉取到用户自有仓库的路径前缀下 |
| SyncRun | 一次推送或拉取操作的会话记录 |
| 开源仓库 | 本产品的公开 GitHub 代码与文档仓库（与应用内脑图 Sync 目标仓库通常不是同一个） |

视觉与组件规格见 → [视觉设计规范](./design-system.md)。
